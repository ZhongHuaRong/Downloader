# 网页视频识别与 m3u8 下载集成方案

状态：主程序已实现 m3u8 直链、网页识别、多选下载、预览及按标题命名，独立探测工具继续保留。

运行：`python.exe .\src\main.pyw`。首次使用网页识别时安装可选依赖：`python.exe -m pip install playwright`。优先使用本机 Edge / Chrome；没有可用浏览器时执行 `python.exe -m playwright install chromium`。普通下载与 m3u8 直链不依赖 Playwright。FFmpeg 仍在现有设置页选择目录并检测。

网页入口：粘贴链接，展开“高级选项”并点击“识别视频”；自动识别未取得资源时可选“浏览器中识别”，在独立浏览器操作后点击“完成识别”。勾选条目、确认文件名后点击“下载已选”。点击缩略图可以重新获取预览。

## 1. 范围和任务关系

- 网页识别是创建任务前的步骤：输入网页、发现资源、确认文件名、勾选下载。
- 首版资源类型限定为独立 MP4 和 m3u8。MP4 交给现有单文件下载，m3u8 交给新增的分片下载、按需解密和合并流程。
- 一次勾选多个视频，创建多个独立任务；一个 m3u8 视频内部的分片仍属于同一个任务。
- 直接输入 m3u8 和网页识别得到的 m3u8 最终使用同一种任务参数和下载流程。
- 普通文件、漫画编号批量下载继续按现有规则运行。
- 优先做到操作顺手并符合现有结构，再按实际职责划分代码，不引入通用任务框架或插件系统。

## 2. 界面与交互

### 2.1 链接入口

保留 `NewUrlPage.qml` 的源路径和目标目录。普通 URL 进入现有 HTTP 配置；路径以 `.m3u8` 结尾的 URL 进入原生 m3u8 配置，识别时忽略查询参数，保留实际请求 URL 中的全部参数。

HTTP 配置中，在下载按钮上方增加可折叠的“高级选项”，展开后以带内边距的浅色边框区域统一展示识别操作、识别状态、视频信息和资源子项。粘贴网页本身不启动浏览器，点击后才开始识别。识别失败或没有资源时，普通下载仍可操作。

识别成功后，视频结果区显示在高级选项框内，普通 HTTP 的全局文件名、数量不参与视频任务提交。收起高级选项时，识别操作、状态、视频信息和资源子项一起隐藏，保留勾选与已编辑的文件名。

### 2.2 视频结果区

```text
source Path：[网页或 m3u8 链接]
target Path：[下载目录] [选择路径]

▾ 高级选项
  [识别视频]

  已发现 3 组资源 · 已选 1 组
  发布标题：示例视频
  发布时间：2026-10-06

  ☑ [预览图] 资源 1 · M3U8 · 04:16  [720p ▾]
    文件名：[video.mkv             ] [按标题命名]

  ☐ [暂无预览，点击获取] 资源 2 · MP4 · 00:30
  ☐ [预览图] 资源 3 · M3U8 · 12:00

[下载已选（1）]
```

- 每个条目独立保存勾选状态、文件名和所选清晰度。点击条目的空白或文字区域也可切换勾选；预览、输入框、清晰度和按钮各自响应操作。
- 勾选后直接显示文件名输入框和“按标题命名”按钮；未勾选时隐藏这一行。
- 不设置“下载设置”标题，不增加条目展开箭头或第二层折叠节点。
- 取消勾选时保留已修改的文件名，再次勾选恢复。切换清晰度、更新元信息也不覆盖手动名称。
- 保存目录统一使用顶部 `target Path`，首版不增加每项单独的目录输入。原生 m3u8 配置和网页条目显示当前清晰度的视频分片数，独立音轨不计入该数字；统计中和读取失败分别显示状态，不以 0 代替未知数量。
- 无选中项时下载按钮不可用。直接 m3u8 默认作为一个待确认的视频任务；网页发现多组时由用户选择。
- 提交前统一校验勾选项及文件名。m3u8 任务先确认 FFmpeg 检测成功，缺失时在当前页面引导设置；MP4 单文件下载不依赖 FFmpeg。
- 视频来源不改变配置的含义、默认值和校验规则。原生 m3u8 配置与网页结果条目分别用独立 QML 文件实现，基础控件沿用现有组件。

### 2.3 预览

- 默认自动获取预览，先使用可确认对应资源的封面或播放器画面；缺失时后台使用 FFmpeg 抽帧。预览通过 Qt 异步下载前两个 HLS 分片及必要的密钥/初始化资源，或最多 12 MiB 的 MP4 开头样本，FFmpeg 读取本地样本；单次预览限制总量和超时，复用 Qt 代理及按来源传递的请求头。
- 同一主清单下的清晰度共用一份预览，按可见条目调度，限制并发和超时。
- 点击预览区域获取、重新获取或失败重试；不增加独立“获取预览”按钮。
- 获取中在图片区显示状态，预览点击与勾选互不影响。
- 无法确认关联的画面不套到其它资源上，显示“暂无预览”。
- 预览不阻塞选择、改名和下载。MP4 预览失败也不改变其单文件下载能力。

## 3. 网页标题、日期和媒体的获取

### 3.1 用户提供页面的优先位置

| 信息 | 优先选择器 | 处理 |
| --- | --- | --- |
| 发布标题 | `#dle-content article.page .page__header h1` | 读取正文文本，清理首尾和重复空白 |
| 发布时间 | `#dle-content article.page .page__meta-item--date` | 提取日期，保留原文并规范为 `YYYY-MM-DD` |
| 播放器区域 | `#dle-content article.page .page__player` | 定位实际播放器及其 iframe，辅助触发播放和关联媒体 |

正文标题直接读取上述 h1。以截图中的日期格式为例，“2026年10月6日”规范后是 `2026-10-06`；本文的“示例视频”仅作命名占位。信息来自网页正文，不使用电脑当天日期，也不做视频画面 OCR。

选择器未命中时，可回退到页面已有的 VideoObject、Open Graph、明确的发布日期元素；没有可靠日期就显示“未获取”。iframe 的通用标题、广告标题不覆盖正文发布信息。不从 URL 中的年份或文件修改时间猜测发布日期。

### 3.2 按标题命名

- 初始文件名始终由资源 URL 提供：MP4 保留文件名；m3u8 去掉清单扩展名并加合并输出扩展名，例如 `video.m3u8` 对应 `video.mkv`。
- 按钮“按标题命名”使用界面展示的发布信息生成 `[20261006]示例视频.mkv`；文件名日期采用 `YYYYMMDD`，日期与标题之间不留空格。
- 只有标题时生成 `示例视频.mkv`，不生成空日期括号；没有标题时保留 URL 默认名，按钮不可用。
- 标题已包含相同日期时避免重复添加。生成后做 Windows 文件名合法性、末尾空白和点、保留名称及重名检查。
- 点击按钮才回填，保留后续手动修改。扩展名与该资源的下载或合并格式对应。
- 创建多选任务前，同时检查本批次、现有任务和磁盘文件的重名，避免两项同时得到相同输出名。

### 3.3 自动发现媒体

先检查 HTML 和播放器配置，再由独立工作线程运行浏览器，监听实际请求及小型页面/接口响应，保留状态和来源。

先观察页面加载请求，必要时尝试在正文播放器区域静音播放或触发明确的播放控件；覆盖其 iframe。需要登录、验证或特殊操作时，允许转为可见浏览器由用户继续。支持取消识别，源链接变化后的旧结果不回填新页面。

根据播放清单的实际引用关系归并主清单和子清单。HLS 已引用的 TS、m4s、初始化 MP4 不作为独立成品候选。独立 MP4 可以是正片或广告，保留预览供用户选择，不凭扩展名认定用途。其它资源类型首版不作为可下载项。

每组保留实际媒体地址、清晰度、原网页地址、必要请求上下文和发布信息。完整保留签名查询参数；Referer、User-Agent 随任务传递，Cookie/Authorization 按适用来源发送，不保存播放器当次的 Range 作为续传参数。

## 4. m3u8 下载、工作目录和恢复

### 4.1 处理流程

```text
读取播放清单 → 确定清晰度和关联音轨 → 下载资源 → 按需解密合并 → 发布成品
```

- m3u8 的分片数量、顺序和地址来自清单；漫画仍按现有编号规则生成地址。
- 主清单选择清晰度后，关联音轨应一起处理，避免只输出无声视频。
- 相对 URI 根据响应最终地址解析，处理 HTTP 重定向。
- 点播下载支持普通分片、初始化片段和 `AES-128`/`NONE`。AES 的密钥、IV、媒体序号和密钥轮换依照清单处理，不新增解密配置。
- 保留 HLS 的必要标签，生成本地播放清单供 FFmpeg 读取，从而处理解密和合并。不能直接套用旧脚本从 1 开始计算 IV 的假设。
- 字节范围分片必须保留正确映射；尚未实现的 HLS 特性需明确提示。加密字节范围分片、直播录制、DASH、SAMPLE-AES/DRM 不在首版范围。
- 下载先写分片临时文件，确认响应和写入成功后再标记该片完成。恢复时核对配置和文件状态。

### 4.2 目录与成品

工作目录按最终输出名生成，URL 中的日期、UUID、清晰度目录只用于解析资源地址。

```text
下载目录/
  视频A.mkv                       # 已完成的合并视频
  视频B.mp4                       # 已完成的单文件

  视频C.mkv.tmp/                  # 尚未完成的 m3u8 任务
    视频C.mkv.tmp.cfg             # 任务参数、阶段、分片映射与完成状态
    original.m3u8
    local.m3u8
    segments/...
    keys/...                      # 按需
    merge.part.mkv
```

任务公开保存位置始终是用户选择的父目录。每项视频在创建前独立确认成品文件名，内部的分片文件映射由任务维护。

默认合并输出 MKV，与外部脚本一致；如提供 MP4 输出，需作为明确的合并格式处理。合并成功并确认输出存在且非空后，移动并重命名到父目录，再后台清理本任务工作目录，并记录成品保存及清理结果；完成任务销毁时不再写回配置。发布成品时再次检查重名，已有文件不覆盖。失败或中断时保留工作目录，合并失败只重试合并。

暂停下载会停止网络请求并保存进度。合并阶段显示“停止合并”，再次开始时重新合并；人为停止不能因 FFmpeg 返回成功码而误判任务完成。

### 4.3 任务生命周期

注册表继续保存任务摘要，分片细节保存在工作目录配置中。摘要增加必要的任务类型、来源和请求信息，随“正在下载 / 已完成 / 已删除”迁移；旧记录缺少新增字段时按原 HTTP 规则处理。

一个 m3u8 即使只有一个分片，也仍是 m3u8 任务，不能用数量推断类型。普通、漫画、MP4、m3u8 的暂停、重试、重启恢复和列表迁移均需按明确类型分发。

永久删除和全部删除先停止网络与合并进程、释放文件，再清理自身的临时文件或工作目录，保留父目录已完成的视频。漫画图片和正式目录沿用现有保留规则。

GUI 主线程只接收信号、更新状态以及使用异步 Qt 网络/QProcess。Playwright 在工作线程创建、使用和关闭，工作线程不直接操作界面或主线程 QObject。

FFmpeg 路径只来自现有设置检测结果。代理沿用现有代理设置，浏览器显式传入代理，抽帧样本经 Qt 网络获取。只在用户使用网页识别时检查 Playwright/浏览器依赖，不让它影响普通下载启动。

## 6. 实施顺序和验证

1. **工具和方案归档**：将探测脚本移至 tools，修正文档中的运行命令，记录本方案。此步不改变主程序行为；工具运行命令为 `python.exe tools/probe_video.py`。
2. **m3u8 直链完整流程**：完成原生配置、类型分发、分片与配置、按需解密合并、成品移出和恢复。先把一条链接完整下载做好。
3. **网页前置识别**：完成正文标题/日期、自动发现与手动回退、独立结果列表、多选、MP4 请求上下文以及接入同一 m3u8 下载入口。
4. **预览和自动命名**：接入自动预览、图片区点击、按标题命名、清晰度分组和手动名称保留，完成已确认交互后一起验收。

每个功能点独立提交并验证，通过后推送。只使用本机模拟页面和媒体做自动验证，不要求用户提供或公开真实网址及访问凭据。

验收重点：

- 截图所示 DOM 能取得正确正文标题和日期，生成 `[20261006]示例视频.mkv`；缺失字段有确定的回退。
- 原生 m3u8 与网页发现的同一清单产生相同行为；勾选两项创建两个任务，每项文件名独立；清晰度切换更新该媒体清单的视频分片数。
- 勾选控制文件名行显示，取消后保留改名；仅高级选项保留折叠节点；预览点击不影响勾选。
- 主/子清单归组，切换清晰度不重置文件名；广告 MP4 不复用正片截图，预览失败不阻塞下载。
- 带查询参数、相对地址、重定向、请求头、代理、空格/中文路径、重复文件名正常处理。
- 普通点播、加密/未加密、密钥轮换、关联音轨和初始化资源能正确合并；不支持的特性明确报错并保留已下载资料。
- 分片失败/半片、暂停、退出重开、合并中断、合并失败重试、移入已删除和全部删除均保留正确任务状态与成品。
- 大文件进度使用合适的 64 位数据表示，旧普通和漫画任务的下载、恢复与文件布局不回归。

当前已验证的工具能力：浏览器网络发现、iframe、无后缀 m3u8、播放器截图/封面、主子清单分组、清晰度和预览报告。独立工具保持原有手动验证用途，主程序已补齐下载集成、FFmpeg 样本抽帧、自动触发播放和正文发布信息提取。大 MP4 若索引只在文件末尾，开头样本可能无法产生预览，仍可正常下载。

## 7. 实施验证记录

使用隔离的 Windows Python / PyQt5 / Edge 和本机生成的媒体、页面完成验证，未使用真实站点地址或凭据：

- QML 新建任务、已完成/已删除迁移与缓存清理通过检查；普通 HTTP、漫画连续编号、错误响应和不支持 Range 的续传保持正确行为。

- 自动/点击预览、按标题命名、勾选隐藏、清晰度切换和手动名称保留通过检查；浏览器与预览共用显式代理，支持手动浏览器完成、取消以及可选依赖缺失提示。

体验优化补验：通过真实鼠标点击验证整条切换、复选框、预览、输入框、标题按钮和清晰度互不干扰；验证高级选项展示盒、不同清晰度分片数、统计失败、`[YYYYMMDD]标题` 命名，以及控制台和文件双份日志。

高级选项归组补验：识别操作、状态、元信息和资源子项均位于同一展示框，折叠后保留编辑状态；滚动预览按实际视口定位。清理时序测试覆盖任务完成销毁与后台删除并行，防止配置写回导致缓存目录残留。
